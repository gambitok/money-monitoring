# План

Статуси: ⬜ не почато · 🟡 в роботі · ✅ готово

## Етап 0. Каркас ✅

- `package.json` (ESM, Node 24), залежності `express@5` і `better-sqlite3`.
- `server.js` віддає статику з `public/` і `GET /api/health`.
- `src/db.js`: підключення, WAL, foreign keys, механізм міграцій через `user_version`.
- `npm test` з першим тестом на health.
- `launch.ps1`, оновлений README.

## Етап 1. Модель даних ✅

- Міграція 1: таблиці `categories` і `transactions` з індексами `(occurred_on)` і `(category_id)`.
- `src/validate.js`: `parseAmount("1 234,50") → 123450`, перевірка дати, правило «без категорії потрібен опис».
- Unit-тести на парсинг сум і валідацію.

## Етап 2. Щоденне введення ⬜

- API: `GET /api/transactions?from&to&type&category_id`, `POST`, `PATCH /:id`, `DELETE /:id`.
- UI: форма швидкого введення (тип, сума, дата за замовчуванням сьогодні, категорія, опис), список операцій за обраний день або тиждень, редагування і видалення.
- Підсумок дня: доходи, витрати, баланс.

## Етап 3. Категорії ⬜

- API: `GET /api/categories?type`, `POST`, `PATCH /:id`, `DELETE /:id` (архівація, якщо до категорії прив'язані операції).
- UI: сторінка категорій і створення нової категорії прямо з форми операції.

## Етап 4. Зведена таблиця ⬜

- API: `GET /api/summary?from&to&group=month` повертає рядки категорій (окремо доходи і витрати), колонки місяців і підсумки.
- UI: таблиця «категорія × місяць» з рядком «Без категорії», підсумки по рядках і колонках, баланс за місяць, фільтр за періодом.
- Клік по клітинці відкриває список операцій цієї категорії за цей місяць.

## Етап 5. Імпорт старих витрат з Excel ⬜

Джерело: власна Excel-таблиця власника (`.xlsx`). Перед стартом етапу попросити зразок файлу або опис колонок.

- Файл `.xlsx` надсилається на `POST /api/import/preview` як `application/octet-stream` (`express.raw`), без multer.
- Парсинг `.xlsx` на сервері. Кандидат — `read-excel-file` (легкий). Пакет `xlsx` (SheetJS) з npm застарів і має відомі вразливості, тому його не беремо. Залежність погодити окремо.
- Вибір аркуша, зіставлення колонок (дата, сума, тип або знак суми, опис, категорія). Excel-дати приходять як серійні числа або Date, їх треба нормалізувати в `YYYY-MM-DD`.
- Попередній перегляд: нові рядки, дублікати (`import_hash` = sha256 від дати, суми і нормалізованого опису), помилки.
- `POST /api/import/commit` записує все в одній транзакції. Відсутні категорії створюються автоматично.
- Запасний варіант без залежності: зберегти таблицю з Excel як CSV і парсити її.

## Пізніше (поза базою)

- Правила автокатегоризації («опис містить X → категорія Y»).
- Графіки за місяцями і категоріями.
- Кілька валют.
- Експорт CSV і бекап `money.db`.

## Рішення

- Імпорт старих витрат — з власної Excel-таблиці (`.xlsx`). Банківські виписки поки не потрібні.
- Валюта — тільки гривня. Колонка `currency` з `DEFAULT 'UAH'` залишається на майбутнє, але в UI та API вибору валюти немає.
